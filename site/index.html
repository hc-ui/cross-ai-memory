写入门闩

方法写在 SPEC.md。实现可以换，门闩不该漂。

  1. 读自包含问题不准进库。否则先 MEMORY.md，再索引，再最少的几篇。默认深度 standard，不许通读。
  2. 写当前这句话里要有「记住 / 同意写入」。先提案，一个主题一篇正文。改之前记哈希，文件被人改过就停。
  3. 核写完跑 aimem check。本地提交用批次号。推送要另说「同意推送」。
  4. 采采集器只扫本地会话、出清单。commit 只推进检查点，不是 git，不是改正文。

冲突：你现在说的，大于旧笔记。刚核过的机器事实，大于模型自己记得的。两边打架就两句都留着，不许悄悄覆盖。

命令行会拦什么

零依赖。它查断链、重复标题、过期快照、没编进索引、从 MEMORY.md 走不到的篇、以及疑似 Token。

pip install git+https://github.com/hc-ui/cross-ai-memory.git
aimem tour
aimem rule
aimem check examples/lin-ke
aimem collect scan

跟「让 AI 自己记」差在哪

厂商记忆向量自动记这本笔记
你能打开吗通常不能一块块切片能打开、能搜、能 diff
写错了难改干净下周当成事实改一篇，否过的留在原页
跨产品各记各的各嵌各的同一个文件夹
谁决定写入模型模型你。没点头就不是事实

为什么现在值得做

用 AI 的人会越来越多。一个人同时用两家、三家，也会越来越普通。厂商不会帮你在 Cursor 和 Claude 之间同步「上周拍板的那件事」。你需要一本自己的记忆，不是六本厂商记忆。

自动记忆失败得很危险：它写错了，还接着用。这套方法失败得很无聊：你忘了写一条。
